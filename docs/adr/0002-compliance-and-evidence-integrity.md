# ADR-0002: 合规拦截与证据完整性机制

**Status**: Accepted
**Date**: 2026-10-12

## Context

题目合规红线是"零容忍"（不得输出确定性涨跌预测、收益承诺或直接买卖建议；核心结论必须能回到原始字段）。grill-with-docs 盘问中发现两个需要加固的默认假设：

1. 合规拦截若只靠关键词清单，散户口语（"能上车吗""要不要割肉""还能拿吗"）必然漏网。
2. 证据角标 `[^ref_X]` 若允许 LLM 自由生成，模型可能编造不存在的 ref_id 或引用错配，违反"结论必须能回到原始字段"。
3. 中性问题（"中际旭创怎么样"）若直接分支持/反对，三栏失去辩证基准。

## Decision

1. **意图级合规拦截 + 关键词双保险**：LLM 判断用户是否在索取买卖决策（意图级），叠加关键词清单（买入/卖出/加仓/止损/满仓/翻倍/保本/涨停等）双保险。命中后柔性引导至基本面核验，不粗暴拒答。
2. **证据角标强制校验**：每个工具返回 payload 携带网关生成的 `refId`；前端渲染时强制校验角标必须命中本轮工具实际返回的 refId 集合，否则渲染为灰色"引用失效"标记且不响应点击。存证抽屉数据以工具原始 payload 为准，不信正文转述。
3. **命题重构前置**：中性问题先由 LLM 重构为可证伪命题（如"中际旭创当前业绩强劲、无重大风险"），再围绕该命题组织支持/反对证据。
4. **存证抽屉双层展示**：默认展示关键字段人类可读摘要（服务普通用户）+ 可折叠的完整原始 JSON（满足评委下钻"回到原始字段"），显著标注数据源、时间戳与实时/降级状态。

## Consequences

### 正面
- 合规拦截覆盖散户口语，不因关键词清单漏网而翻车。
- 证据角标从"LLM 自律"变为"前端强制校验"，杜绝编造引用。
- 中性问题通过命题重构获得辩证基准，三栏证据始终有意义。

### 负面 / 代价
- 意图级拦截依赖 LLM 判断，存在误判可能（把正常研究问题误判为索取买卖建议），需通过柔性引导话术缓解（不粗暴拒答，而是转化话题）。
- 前端角标校验增加实现复杂度，但这是题目核心考点，值得投入。

## 补充决策（grill 第二轮，2026-10-12）

5. **智能追问必须过合规且必须是核验向**：底部 3 个追问按钮由 LLM 在本轮末尾生成（保证“逻辑递进”，不用死模板），但必须复用意图级合规过滤，剔除任何隐含买卖导向的追问。追问只能是“证伪/下钻/对比”向（如“同行竞品毛利率对比？”），绝不能是“操作”向（如“要不要买”）。

## 审查后修正（2026-10-12，T1 双轴 code-review 发现）

6. **合规拦截必须走 UI 消息流协议**：拦截响应曾用 `text/plain` 返回，与正常路径的 `text/event-stream` 不一致，客户端 `useChat` 无法解析（实测发现）。修正为统一经 `createUIMessageStreamResponse` 返回。
7. **合规关键词层必须有研究性语境过滤**：裸"买入/卖出"在财务语境中多为术语名词（"北向资金在买入吗""机构评级是买入"），实测假阳性严重。修正为：显式索取句式 > 收益承诺/杠杆/满仓类 > 裸买卖词（仅非研究性语境拦截）。研究性问题交由意图层判断，不误杀。

# SPEC-01: FinBuddy - 投资命题核验与理性算账智能体

**Status**: ready-for-agent  
**Type**: spec  

---

## Problem Statement

缺乏专业投研背景的普通个人投资者每天面对海量碎片化、高噪音的财经资讯（异动行情、社交媒体传闻、晦涩研报及公告）。当盘中出现剧烈波动或负面传闻时，用户无法理解专业金融术语对标的财务底线的实质冲击，也无法辨识信息真伪，从而陷入焦虑并在恐慌中追涨杀跌。现存资讯工具仅做机械式信息聚合，而大模型通用对话工具极易产生数值幻觉或非法给出买卖指令。用户迫切需要一个能听懂自然语言命题、自动调数验真、客观对齐多空证据并提供确定性底线算账的投研伙伴。

---

## Solution

构建 **FinBuddy** —— 一款基于 Next.js 14 全栈架构与 Vercel AI SDK 的 AI Native 个人投研助手。  
用户输入任意自然语言投资疑问或传言后，系统：
1. **合规拦截与命题拆解**：自动平滑拦截直接买卖指令，将模糊命题拆解为 2~3 个可证伪的微观子问题；
2. **多源调数与三级降级**：调用结构化行情 API、官方公告/新闻检索工具（支持 Mock 自动降级），获取高置信度原始材料；
3. **多空证据链对齐**：将信息严谨归类为【支持证据】、【反对证据】与【无法验证项】，杜绝片面偏见；
4. **确定性敏感性算账**：外挂量化计算公式联动滑块，让用户直观调整变量测算经营利润冲击底线；
5. **玻璃盒存证抽屉**：以问财风格呈现思考时间轴与条件标签，点击角标滑出原始存证切片，实现“结论可追溯、推理可复核”。

---

## User Stories

1. As an 普通投资者, I want to 在搜索框输入大白话投资传言或疑问（如“中际旭创大客户砍单传闻业绩会崩吗”）, so that 我无需学习复杂的金融查询语法就能发起深度投研分析。
2. As an 普通投资者, I want to 在首页看到 2~3 个预置的典型热门市场案例（如中际旭创砍单核验、宁德时代固态电池冲击）, so that 我能一键体验完整分析链路，降低首次使用门槛。
3. As an 普通投资者, I want to 当我急躁追问“现在该抄底还是割肉”时，系统不粗暴拒绝我，而是柔性引导为“我们来看看砍单真伪和最坏情况下的利润底线”, so that 获得专业的情绪平复与客观决策辅助。
4. As an 普通投资者, I want to 看到系统将我的复杂问题拆解为清晰的意图标签（如 [标的: 中际旭创] [事件: 砍单传言] [核验维度: 财务支撑与官方披露]）, so that 我清晰了解 AI 的理解是否准确。
5. As an 普通投资者, I want to 点击或删除意图标签, so that 我能就地微调分析范围而无需重新输入整段文字。
6. As an 普通投资者, I want to 展开查看折叠的“思考过程时间轴”, so that 我能看到 AI 调取了哪些接口、搜索了哪些公告、耗时多少秒。
7. As an 普通投资者, I want to 在分析结果中一眼看清三栏证据对比（支持证据、反对证据、无法验证项）, so that 我不会被单方面的自媒体情绪带偏。
8. As an 普通投资者, I want to 看到“无法验证项”被明确标注为“信息真空期 / 尚未到官方披露节点”, so that 我明白当前未知风险的边界。
9. As an 普通投资者, I want to 点击正文中的存证角标（如 [证1]、[财报]）, so that 右侧能平滑滑出存证抽屉查看原始报文、公告披露日期与计算口径。
10. As an 普通投资者, I want to 在存证抽屉中看到数据源状态（如“同花顺接口实时返回”或“触发降级使用权威缓存”）, so that 我确信数据的权威度。
11. As an 普通投资者, I want to 拖动交互式的“营收冲击推演滑块”（如调整营收整体下滑幅度 5%~30%）, so that 下方的净利润冲击测算卡片实时联动重新计算，无需等待 AI 重新生成。
12. As an 普通投资者, I want to 敏感性测算的数字是由严密的数学公式计算出来的而非 LLM 编造的, so that 保证底线测算的绝对准确性。
13. As an 普通投资者, I want to 在回答底部看到 3 个符合逻辑递进的智能追问推荐按钮（如“其三季报毛利率能否抵御冲击？”、“同行竞品是否有类似披露？”）, so that 我能一键下钻多轮分析。
14. As an 普通投资者, I want to 点击输入框旁的“清空上下文”按钮, so that 我能快速切换到全新标的进行研究，避免上一只股票的记忆污染当前会话。

## Implementation Decisions

### 1. 全栈架构选型
- 采用 **Next.js 14 App Router + TypeScript + Tailwind CSS** 单一仓库全栈架构。
- 使用 **Vercel AI SDK (`ai` + `@ai-sdk/deepseek` / `@ai-sdk/openai-compatible`)** 实现服务端的 Agent 多步循环（Multi-step tool calling）与客户端流式渲染（`useChat`）。
- 图表与交互组件使用 **Lucide React** 图标库与原生 React 动画状态机。

### 2. 模块划分与接口契约
系统划分为三大单向解耦模块：

```
[UI 交互层 (Presentation)] 
       │ 触发 dispatch / 请求
       ▼
[Agent 编排与模型层 (Orchestrator - API Route)]
       │ 调用 tools
       ▼
[金融数据网关与降级层 (Financial Gateway)]
```

#### 数据网关契约 (Financial Gateway)
统一暴露三大标准工具函数供 Agent 自主调用：
- `lookupStockSnapshot(ticker: string)`: 返回股票实时价格、涨跌幅、估值（PE/PB）及主力资金概况。
- `lookupFinancialReport(ticker: string, period?: string)`: 返回近 3 期营业收入、归母净利润、销售毛利率及关键在手订单指标。
- `searchAnnouncementsAndNews(ticker: string, keyword: string)`: 检索法定公告披露、互动易董秘问答与主流财经新闻。

#### 网关三级容灾策略
- **L1 实时层**：优先调用公开免费金融数据接口/扶摇接口；
- **L2 降级层**：若请求超时 (>3s) 或返回非 200，熔断降级至本地预置的标准化 JSON 存证库，并在返回 payload 中附加 `isFallback: true` 标记；
- **L3 知识层**：若查询无结果，向 Agent 注入“信息真空期”上下文，驱动模型将该事项明确归类为【无法验证项】。

### 3. Agent 核心推理与结构化契约
- 后端通过 `streamText` 与系统 Prompt 强制约束输出结构：
  - `<thinking>` 标签包裹拆解思考步骤；
  - 正文严格遵循【意图解析】、【核心研判】、【三栏证据对比】、【敏感性测算入口】与【追问推荐】的 Markdown 规范；
  - 引用数据必须挂载格式为 `[^ref_id]` 的角标。
- 前端 `useChat` 接收流式数据，通过状态机自动解析角标并与右侧 Evidence Drawer 建立响应式联动。

### 4. 确定性敏感性推演计算引擎 (Client-side Formula Engine)
- 敏感性测算完全运行在客户端（React State），拒绝 LLM 参与数值算术。
- 采用**营收冲击推演**（见 ADR-0001），不引入无法实时获取的“客户营收占比”推断参数。内置基准财务联动公式：
  $$\Delta \text{NetProfit} = \text{BaseRevenue} \times \Delta \text{RevenueDeclinePct} \times \text{NetMargin} \times (1 - \text{TaxRate})$$
  其中 $\text{NetMargin}$（净利率）取自扶摇财务指标 `sale_net_interest_ratio` 真实值，$\text{BaseRevenue}$ 取自扶摇利润表 `operating_income` 年化值。
- 用户在 UI 上拖动 `RevenueDeclinePct` 滑块（5% ~ 30%），结果卡片实时以毫秒级刷新净利润冲击区间。
- 大客户集中度、单一合同等无法实时核验的变量归入【无法验证项】（见 ADR-0001）。

## 交互细节决策（grill 第二轮，2026-10-12）

- **意图标签微调**：删除标签 → 自动重新分析（明确收窄意图）；修改标签文本 → 需点确认按钮才重新分析（避免每敲一字调一次付费 API）。
- **存证抽屉布局**：右侧固定抽屉（约 380px），滑出时三栏证据流式压缩，实现“证据与出处同屏对照”。
- **敏感性测算实时性**：滑块 onChange 每帧客户端重算（纯数学零开销），阈值区间随数值联动变色，无需等松手。
- **智能追问**：LLM 生成 3 个递进追问，过合规过滤，只能核验向（见 ADR-0002）。
- **多轮上下文**：带历史但只带“结构化结论摘要”（本轮标的 + 已确认事实），不带完整对话，避免爆 token 与噪音。

---

## 引用防幻觉机制（新增，原方案缺失的关键考点）

题目核心考点“核心结论必须能回到原始字段”要求角标不可被模型编造。规定：
- 每个工具调用的返回 payload 必须携带 `refId` 字段（由网关在服务端生成，如 `ref_1`, `ref_2`）；
- Agent 只能在正文中引用本轮工具实际返回过的 `refId`；
- 前端渲染时强制校验：若角标 `[^ref_X]` 不在本轮工具返回集合内，渲染为灰色“引用失效”标记，且不响应点击；
- 存证抽屉的数据源以工具返回的原始 payload 为准，不信正文转述。

---

## Out of Scope

- 真实证券账户的下单交易与资金结算接口。
- 用户多账号注册、登录态与权限体系（采用本地匿名存储自选与历史记录）。
- 移动端 App / 微信小程序专用排版适配（优先保障 Web 桌面端高密度专业交互体验）。
- 复杂图神经网络（GNN）多智能体博弈（单 Agent 多工具循环足以高质量满足需求）。

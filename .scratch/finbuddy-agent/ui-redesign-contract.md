# FinBuddy 前端 UI 重做 —— 设计契约（binding）

> 本文是**派发给 UI 实现 subagent 的硬约束**。它不是建议清单，是验收标准。
> 每条都注明「为什么」与「怎么验」，凡标【红线】者不得以任何理由改动。

---

## 0. 背景与目标

**现状**：深色 slate 工作台（`bg-slate-950`）。功能完整、测试全绿，但用户评价
「整体 UI 风格太丑，包括颜色、布局、字体大小、排版」，且指出要「朝同花顺靠拢」。

**目标**：改为**浅色问财风对话式界面**。

**关键事实（调研实证，已由我独立从 iwencai.com 线上 bundle 复核）**：
问财 web 对话页是**浅色底 + 蓝主色 + 红点缀**，不是深色、也不是全红。
现有深色实现与该语言**方向相反**。

## 1. 设计 token（数值均已实证或经 WCAG 计算，**不得自行更换**）

### 1.1 颜色

```ts
// tailwind.config.ts — 全部作为 theme.extend.colors 落地
brand: {
  DEFAULT: '#165dff',   // 主色：按钮/链接/激活态（实证：问财 --brand-text-color）
  hover:   '#136dff',   // 实证
  bg:      '#f0f4ff',   // 浅底（实证）
},
chat: {
  user:    '#d3e0ff',   // 用户气泡底（实证：--chat-right-bubble-bg-color:"#d3e0ff"）
  ai:      '#ffffff',   // AI 气泡/卡片底（实证：--chat-left-bubble-bg-color:"#fff"）
},
ink: {                  // 文字层级（实证）
  1: '#10131f',         // 一级：结论、标题   对比度 16.8:1 ✅
  2: '#5e606a',         // 二级：说明         对比度  5.7:1 ✅
  3: '#8f9198',         // 三级：仅限装饰/大字号，**正文不得使用**（2.9:1 ✗）
},
line:  { DEFAULT: '#eaeaeb', strong: '#dddde0' },  // 边框（实证）
page:  { DEFAULT: '#f4f4f5', alt: '#fafafa' },     // 页底/斑马纹（实证）
```

**语义色（我按 WCAG AA 计算后选定，不是拍脑袋）**：

```ts
// A股涨跌 —— 必须与"证据方向"色**分离**，见 §3.2
rise: '#c62828',   // 涨（A股红涨）白底 5.62:1 ✅
fall: '#0f7b3f',   // 跌（A股绿跌）白底 5.35:1 ✅
// 注：问财品牌红 #e93030 在白底仅 4.26:1，**不达 AA**，故涨跌色深一档。
//     品牌红 #e93030 仍用于 logo 角标/发送按钮渐变等**小面积非文字**处。

// 三栏证据方向（避开涨跌语义）
evidence: {
  support:   '#1d4ed8',  // 支持证据 白底 6.70:1 ✅
  against:   '#b45309',  // 反对证据 白底 5.02:1 ✅
  unknown:   '#475569',  // 无法验证项 白底 7.58:1 ✅
},
warn: '#b45309',   // 降级指示灯文字（与 against 同族，语义不同但都需醒目）
```

### 1.2 字号阶梯（实证：问财 CSS 频次 14px×45 > 12px×33 > 16px×20）

```ts
fontSize: {
  aux:   ['12px', '18px'],   // 辅助/标签/角标
  body:  ['14px', '22px'],   // 正文（**最小正文**）
  lead:  ['15px', '24px'],   // 长段落正文
  card:  ['16px', '24px'],   // 卡片标题
  kpi:   ['20px', '28px'],   // 关键数值
  hero:  ['28px', '36px'],   // 页面级 KPI（少用）
},
```

**【红线 R1】正文最小 14px。** 现状有 **32 处 11px + 12 处 10px**，这是用户抱怨
「字体大小」的直接原因。低于 12px 只允许出现在：角标数字、图表刻度。

### 1.3 圆角 / 间距

```ts
borderRadius: { chip: '4px', card: '8px', bubble: '12px', modal: '16px' },
```
（实证：问财 4px×23 > 8px×16，小圆角为主。卡片内边距 12–16px。）

## 2. 布局（对话式，这是用户明确要的）

### 2.1 结构

```
┌─────────────────────────────────────────┐
│  顶栏：FinBuddy · 核验助手     [清空上下文]  │  ← 细，不抢视觉
├─────────────────────────────────────────┤
│                                         │
│  对话流（单栏，max-width ~880px 居中）      │
│   · 用户提问：右对齐浅蓝气泡 #d3e0ff        │
│   · AI 回答：全宽区块，白底                 │
│     └ 结论段 → 核验结论卡 → 三栏证据卡      │
│        → 数据表格 → 测算卡 → 追问          │
│                                         │
│  （自动滚动到最新；用户上滚则不打扰）        │
├─────────────────────────────────────────┤
│  [ 输入框 ................................ ]│  ← sticky 常驻底部
│  内容由 AI 生成，仅供研究参考，不构成投资建议  │  ← 常驻免责
└─────────────────────────────────────────┘
```

### 2.2 三个必须补的交互（现状缺失，是「不像聊天」的根因）

**【必须 B1】输入框 sticky 常驻底部。**
现状在页面**顶部**（DOM 顺序：`<form>` 在轮次列表**之前**）。后果：第 2 轮时
输入框被第 1 轮内容推到上方，要滚回顶部才能追问 → 不像聊天。

**【必须 B2】自动滚动到最新消息。**
现状**完全没有** `scrollIntoView`/`scrollTop`。后果：流式输出时新内容在下方，
用户看不到进度。实现要求：内容增长时滚到底；但**用户主动上滚时不打扰**
（否则读历史时会被强行拽回底部）。

**【必须 B3】消息身份区分。** 用户/AI 两侧需有可辨识的视觉差异（气泡色 + 对齐 +
可选头像/角色标签）。

### 2.3 首屏（空状态）

保留预置案例（零输入体验完整链路），但要**收敛视觉**：不要现在的双列大卡片墙，
改为紧凑的推荐列表/胶囊，让首屏看起来像对话产品的空状态。

## 3. 必须保留的功能（**换皮不得换掉**）

### 3.1 【红线 R2】角标强制校验
编造引用必须渲染为灰色「引用失效」且**不可点击**（ADR-0002 决策 2）。
改变观感可以，**放松校验绝对不行**。

三态：`valid` / `invalid` / `pending`。**pending 也不可点击**（流式中集合未到）。

### 3.2 【红线 R3】A股涨跌色不得与证据方向色混淆
- **涨跌数字**：红涨绿跌（`rise`/`fall`），必须带 `+/-`，必须 `tabular-nums`。
- **三栏证据方向**：用 `evidence.support/against/unknown`（蓝/琥珀/灰），
  **不要用红绿**。

**为什么**：现状是「支持证据=绿 / 反对证据=红」，这是西式 `green=good` 心智。
但 **A股用户的心智是反的（红=涨=好）**，导致「反对证据（红）」给目标用户的
第一直觉像正面信号。把「证据方向」与「涨跌」分到两套色系即可解。

### 3.3 【红线 R4】合规拦截分支
被拦截的轮次**不得渲染三栏证据**，只渲染合规提示。

### 3.4 【红线 R5】降级指示灯
L2 降级存证必须**显著**渲染，文案与日期不得省略。
（原票面文案：`[ ⚠️ 降级存证：外部实时接口超时，已启用权威历史存证 ]`）

### 3.5 其余必须保留
- 思考过程时间轴（步骤状态 + 当前步高亮 + 真实耗时）
- 意图标签（可微调后重跑）
- 命题重构卡片（含「兜底命题」标注）
- 输出契约违规提示（暴露坏消息，不静默）
- 智能追问（点击即发起下一轮）
- 存证抽屉（380px，右侧滑出，原始 JSON 可下钻）
- 敏感性测算卡片（营收下滑区间 + 公式依据）
- 清空上下文

## 4. 反例（调研明确指出的坑，别踩）

1. **把大表格塞进聊天气泡** → 气泡宽 60–75%，12 列表格必然横向滚动 + 字号压到 10px。
   **数据一律出气泡、进全宽卡片。**
2. **深色底 + 红绿涨跌** → 深色上红绿要拉高饱和才可见，结果是"霓虹赌场风"。
3. **把页面染红** → 品牌红只做小面积点睛（问财实证做法）。
4. **流式时只显示转圈** → 40s 无可见进度，用户会刷新重发。必须有步骤时间轴。
5. **字号一刀切放大** → 层级靠 14/12/16/20 的阶梯，不是全局放大。
6. **推理过程平铺** → 默认折叠，避免淹没结论。
7. **伪造精度** → 指标必须标明来源与时间，别让 AI 生成的数字像实时行情。

## 5. 工程约束（本仓库既有纪律，必须遵守）

1. **注释与文档全部用中文**，解释「为什么」而不是「是什么」。
2. **每个模块/组件文件开头**写 doc comment：说明它是什么、抓到什么、漏掉什么。
3. **测试是资产**：现有 422 处 DOM 断言多数测**文本/语义**（换皮安全）。
   - 允许改：`className` 断言、纯样式选择器。
   - **不允许**为了让它通过而删断言。改实现或改断言目标，并在提交信息里说明。
4. **改完必须跑**：`npx vitest run`、`npx tsc --noEmit`、`npx next lint`、
   `npm run build` —— 四条全绿才算完成。
5. **不得引入重型 UI 框架**（如 Ant Design / MUI）。用 Tailwind + 现有组件。
   可选择性引入 `clsx`/`tailwind-merge`（若确有必要）。
6. **不得改变任何 `lib/` 纯逻辑**（23 个单测是资产）。UI 只消费它们的输出。
7. **不得改变 `/api/chat` 的数据协议**（`steps/plan/refs/contract/followups/compliance`）。
8. **演示脚本一致性**：`DEMO.md` 描述的「画面验收点」必须仍被渲染，
   `tests/demo-script-check.test.tsx` 是守卫 —— 若因换皮导致文案变化，
   改 `DEMO.md` 或改守卫，**不得让守卫失效**。

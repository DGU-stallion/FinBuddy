# FinBuddy · 投资命题核验与理性算账智能体

面向普通个人投资者的 **AI Native 投研助手**：输入一句大白话的投资疑问或市场传闻，
系统自动把它**重构为可证伪的投资命题**，调用真实金融数据接口取证，
把证据严格分到【支持证据】【反对证据】【无法验证项】三栏，
并提供**由确定性数学公式（而非大模型）计算**的营收冲击推演。

**核心主张：AI 定性 + 数学定量。**
定性判断（这传闻是什么意思、该查什么）交给大模型；
数值计算（营收下滑 20% 会吃掉多少净利润）交给纯函数公式，零 LLM 参与。

> 本项目**不提供任何投资建议**，不适合作为买卖决策依据。

**仓库**：https://github.com/DGU-stallion/FinBuddy ·

## 30 秒理解它想解决什么

散户面对异动行情和社交媒体传闻时，通常只有两个选择：看自媒体（情绪化、可能编造），
或问通用大模型（会一本正经地编数字、甚至直接给买卖指令）。

FinBuddy 的立场是三条硬规则：

| 硬规则 | 具体做法 | 代码位置 |
|---|---|---|
| **不猜** | 数据缺口不脑补为结论，显式归入【无法验证项】 | `lib/output-contract.ts` |
| **可追溯** | 每条事实挂 `[^ref_X]` 角标，角标必须命中本轮工具真实返回值 | `lib/citations.ts`（服务端与前端**同一实现**） |
| **不越界** | 不输出买卖建议/收益承诺/股价预测；用户索取买卖决策时柔性引导回基本面核验 | `lib/compliance.ts`、`lib/vocabulary.ts` |

## 目标用户、场景与工作流（原题第 1 条）

### 目标用户

**没有专业投研背景的个人投资者**（典型画像：看过几份研报、会用行情软件，但不会自己拉财报科目做测算）。

> 按原题"涉及用户画像/持仓时应使用匿名或构造数据"：本项目**不采集、不存储、不上传**任何真实用户画像或持仓。
> 唯一的本地状态是浏览器 `localStorage` 里的会话标题与对话（本地匿名），不涉及任何个人信息。

### 真实工作流（产品被嵌入的那一步）

```
盘中异动 / 刷到社媒传闻
        │
        ▼
 "这消息是真的吗？会影响我手里的股吗？我该不该动？"   ← 用户此刻的真实问题
        │
        ├─ 现状 A：看自媒体 → 情绪化、可能编造、只给一个方向
        ├─ 现状 B：问通用大模型 → 编数字、甚至直接给买卖指令
        └─ 现状 C：用传统行情/数据终端 → 数据全，但要自己会查、会算、会判断多空
        │
        ▼
 FinBuddy：把它重构为可证伪命题 → 调真实数据取证 → 三栏对齐 → 确定性算账
        │
        ▼
 用户拿到的不是一个结论，而是一张"证据 + 未知边界 + 量化敏感区间"的底稿
```

### 非目标（明确不做）

| 非目标 | 为什么不做 |
|---|---|
| **不下单交易、不接券商账户** | 合规红线；且资金结算与投研核心任务无关 |
| **不输出买卖建议/收益承诺/股价预测** | 原题硬性要求；也避免用户把产品当"荐股" |
| **不做通用闲聊** | 通用聊天不是本产品的价值；会话管理只做投资命题核验这一件事 |
| **不做账号体系 / 云端同步** | 24h 边界内不值得；本地匿名存储已够演示闭环 |
| **不做移动端适配** | 见 `spec.md` 的 Out of Scope；优先保障桌面端高密度专业交互 |

### 成功标准（可衡量）

| 标准 | 衡量方式 | 当前实测 |
|---|---|---|
| 主链路能走通 | 一次提问产出 5 个 data part 齐全 | ✅ 真机：`steps/plan/refs/contract/followups` 齐全 |
| 结论可追溯 | 正文角标是否全部命中本轮工具返回 | ✅ 真机：角标全部可溯源，`invalid = 0` |
| 证据不偏 | 三栏是否都有实质内容（非占位符） | ✅ `lib/output-contract.ts` 把"无/暂无"判为空栏并报违规 |
| 定量不受 LLM 影响 | 拖滑块时 `fetch` 调用数 | ✅ 组件测试断言**零请求** |
| 不越界 | 合规测试集是否全部拦截 | ✅ 真机 `6/6, exit 0` |
| 数据缺失不静默 | 真空期/降级是否显式声明 | ✅ 契约校验 `missing_vacuum_disclosure` / `missing_fallback_disclosure` |

## 为什么需要 LLM / Agent（原题第 2 条）

这是本题最需要"论证"而非"声明"的部分。逐条对比：

| 替代方案 | 它能做到什么 | 它**做不到**什么（而这恰是本产品的核心） |
|---|---|---|
| **规则/正则** | 精确匹配关键词、固定的合规词表拦截 | 无法把"大客户砍单传闻业绩要崩吗"这种**自由中文命题**拆成 2~3 个可核验子问题，也无法决定该查哪几个字段 |
| **搜索** | 找到相关网页/公告 | 找到 ≠ 可核验。搜索结果不会告诉你"这条证据是支持还是反对该命题"，也不会在你查不到时**主动声明信息真空** |
| **传统金融数据产品** | 数据全、字段权威、有现成指标 | 要求用户**自己**知道查什么、怎么解读、多空怎么对齐；散户恰好缺的就是这一步 |
| **人工研究员** | 判断质量最高 | 成本与延迟不可接受（散户不会为一句传闻买一份研报）；且**不可复现**  |

因此本产品把任务**切开**（这也对应开头那句"AI 定性 + 数学定量"）：

| 环节 | 交给谁 | 为什么 |
|---|---|---|
| 听懂口语、重构命题、拆子问题、决定调哪个工具 | **LLM**（`lib/analysis.ts` + `route.ts`） | 自由度太高，规则写不完；这是 LLM 真正擅长且不可替代的地方 |
| 取数、降级、分配 `refId` | **确定性网关**（`lib/gateway.ts`） | 需要可重放、可对账，不能让模型"自己想办法拿数据" |
| 角标是否合法 | **纯函数**（`lib/citations.ts`） | 防幻觉不能交给可能幻觉的那个东西自己判断 |
| 数值测算 | **纯公式**（`lib/sensitivity.ts`，零 LLM） | 数字不能让 LLM 算 —— 这是幻觉风险最高的位置 |
| 合规拦截 | **词表（确定）+ 意图（LLM）双保险** | 两层的误报/漏报模式不同，互为补充 |

**一句话概括增量价值**：通用大模型能把这段话写得更好看，但会把"查不到"写成"看起来正常"；
规则/搜索/传统数据产品不会编，但给不了一张**多空对齐 + 未知边界 + 敏感区间**的底稿。
FinBuddy 的增量在于用工程手段（确定性网关 + 前端强制校验 + 纯公式）把 LLM 的自由度**关在骨架里**。

### ⚠️ 关于密钥：没有 key 时产品会看起来“坏了”（实测结论）

本项目**无内置 mock 模式**，界面能跑起来不等于能给出分析。已在“全新解压副本”上实测：

| 副本里的 key | 评审看到的结果 |
|---|---|
| **四个都没有** | 每次提问均返回 `data-compliance.layer = fail_closed`，正文只说“合规校验服务暂时不可用”。**这是 fail-closed 设计生效，不是 bug**，但看上去像产品挂了 |
| **仅 DEEPSEEK** | 能跑完流程（5 个 data part 齐、三栏齐全），但 `refs = 0`、角标 0 个 —— 因为行情/公告接口无凭证。模型会诚实输出“本轮数据源全部不可用，命题无法验证” |
| **四个全填** | 完整产品：4 条真实存证、16 个角标全部命中（`invalid = 0`）、契约 `ok=true`、追问 3 条 |

   这比让评审自己申请三个国内金融数据 key 更现实。
2. **随包附一份临时 key**：仅当这些 key 愿意短期公开时适用；**用完请立即在服务商后台吊销/轮换**。

3. **陪同时运行**：评审现场或远程共享屏幕，在你自己的机器上跑 `http://localhost:3000`。

> 它不能代替 key —— 标的解析本身就依赖扶摇接口。所以无 key 时不会自动“回退到本地数据”。

### 关于三个"容易被误判成测试脆弱"的真缺陷

**① 一次提问被渲染成两轮（用户三次报告的"还是出现两次"）。**
这是用户看到的那个缺陷。我**前两次都修错了方向**：
先判定为"同 tick 连点"（`inFlight` 闸门，测试全绿但问题依旧），
再判定为"输入法选词的 Enter 误提交"（CDP 复现、红→绿都做了，问题依旧）。
两次都在**客户端提交路径**找原因，**而真因在服务端**。

真因：路由把 `data-steps` / `data-plan` 写在了 `start` **之前**，
而 `start` 由 `merge(..., { sendStart: true })` 带出；
AI SDK 的客户端消息归集于是先因 `data-*` 开一条 assistant 消息，
再因 `start` 开**第二条** ⇒ 单次 HTTP 请求 → 2 条 assistant 消息 → 同一提问渲染两轮。

定位方式（不再靠推理）：真实浏览器 + **真实抓流回放** ——
抓下完整 SSE（1799 个事件）原样重放，稳定复现；再用二分截断定位到
**第 3 个事件**就已出错，最后拿到最小复现：

| 流内顺序 | 客户端 assistant 消息数 |
| --- | --- |
| `data-steps` + `data-plan` | 1 ✅ |
| `data-steps` + `data-plan` + `start` | **2** ❌ |
| `start` + `data-steps` + `data-plan` | 1 ✅ |

修法：显式先写 `start`，并把 `merge` 的 `sendStart` 改为 false。
验证：`tests/route-offline.test.ts` 锁协议顺序 +
`node scripts/single-render-check.mjs` 在真实浏览器里**数渲染出的轮次**，
两层都已做变异测试（改回旧顺序 → 红；恢复 → 绿）。

> **教训**：用户说"还是出现两次"时，前两次我都直接归类到
> "提交动作跑了两遍"。实际上提交确实只发生了一次 ——
> **一次提交、一次请求，却渲染出了两轮**。下次遇到"重复"，
> 要同时怀疑**提交路径**与**渲染路径**，别默认是前者。
> 另一个陷阱：我的第一版回放脚本漏了 `start` 上的 `messageId`，
> 导致脚本"变不红"（没牙齿）—— 测试变不红比测试失败更危险。

**② 中文输入法的 Enter 会被当成提交（一条独立存在的真缺陷）。**
此条**并非**用户看到的"两次"的真因，但缺陷本身真实存在，已修并保留验证：
输入法打字时按 Enter 选词，会被 `<form onSubmit>` 当成提交，
把**未打完的拼音**（`shichang`）发出去。修法是组词状态下在源头 `preventDefault`。
验证脚本：`node scripts/ime-submit-check.mjs`（真实 Chromium，**实测可红**）。

**③ 合规意图层会误伤中性提问。**
真机测试约 1/5 概率失败。抓住现场后发现不是测试脆弱 —— 服务端返回
`data-compliance {layer:"intent"}`，即**「中际旭创怎么样」被合规层拦下了**，
用户拿不到任何核验结果。根因是提示词的"否"示例全是具体事实型提问，
而开放式提问与任何示例都不像。已补判据：**主语是不是"我"、有没有行动诉求**。

### 会话管理

左侧栏可**新建/切换/删除对话**，标题自动取自首轮提问，记录存在
**本机浏览器**（`localStorage`，本地匿名、不上传）。

依据 spec：把"历史记录"列入 Out of Scope 但限定为「本地匿名存储」，
所以只做本地持久化 —— **不做账号体系、云端同步、通用闲聊**。

两个容易被忽略的实现细节（都被单测抓到过）：
- **流式途中不落盘**：否则刷新后看到半句回答，用户会以为是模型坏了。
- **同毫秒写入排序**：`Date.now()` 精度不足以区分连续两次写入，
  会让"最近使用置顶"静默失效，故用单调时间戳。

> 为什么没套用 assistant-ui 这类高 star 对话框架：本项目的难点全在**领域专用呈现**
> （自定义 data part 契约、角标强制校验、三栏证据、确定性测算卡、存证抽屉）。
> 框架的强项是通用聊天，**能替我们做的恰好是已经做完的部分**，真正的难点它替不了；
> 换了还要丢掉既有 500+ 条断言的验证，再对框架的数据模型做一次适配。

### 视觉风格：浅色问财风

界面按**同花顺问财 web 的实际语言**做：浅灰底 `#f4f4f5`、白卡片、蓝主色
`#165dff`、品牌红只做小面积点睛。这组色值是从 iwencai.com 线上资源提取的
实证 token（见 `.scratch/finbuddy-agent/research-wencai-ui.md`）。

刻意做的两件事：

1. **涨跌色与"证据方向"色分离**。三栏证据用蓝/琥珀/灰而非红绿 ——
   A股用户心智里"红=涨=好"，若用红色表示"反对证据"，第一直觉信号是反的。
   红绿只留给行情涨跌数字（`rise`/`fall`）。
2. **承载信息的颜色都过对比度**。品牌红 `#e93030` 照抄到白底只有 4.26:1，
   不达 WCAG AA，故涨跌色深一档（`#c62828` / `#0f7b3f`）。
   品牌色可以照抄，但**承载信息**的颜色不能照抄。

正文最小 14px（辅以 12px 标签、16px 卡片标题），圆角以 4/8px 为主。

### ⚠️ 页面"只有文字没有样式/交互"时怎么办

**症状**：浏览器里只有裸文字，没有配色、卡片、按钮样式，点预置案例没反应。

**原因**：`.next` 构建缓存损坏，导致 Tailwind 生成的 CSS 请求返回 **404**。
最常见触发方式：**在一个正在 `npm run dev` 的目录里又跑了 `npm run build`** ——
dev 与 production 都要写 `.next/`，产物互相污染后会看到
`__webpack_modules__[moduleId] is not a function` 之类的报错。

**修法**（一条命令）：

```bash
npm run clean && npm run dev     # 等价于 rm -rf .next && next dev
# 或直接用：npm run dev:clean
```

**如何 30 秒确认是这个原因**：

```bash
# CSS 应返回 200 且体积可观（~34KB dev / ~21KB prod）；若是 404 即是此问题
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" \
  "http://localhost:3000$(curl -s localhost:3000 | grep -o '/_next/static/css/[^"]*' | head -1)"
```

> 本项目已加守卫测试 `components/tailwind-classes.test.tsx`，专门防另一类
> **不报错的样式失效**：`bg-slate-950/98` 的 `/98` 不在 Tailwind 默认 opacity
> 档位内（档位止于 95/100），会被**静默丢弃** —— 构建成功、lint 零警告、
> 测试全绿，但元素没有背景色。

## 它能做什么

1. **合规拦截**（关键词层 + LLM 意图层双保险）：用户问"要不要割肉"时不是粗暴拒答，
   而是柔性引导为"我们来看看砍单真伪和最坏情况下的利润底线"。
2. **命题重构**：中性问题"中际旭创怎么样"先被重构为可证伪命题，三栏才有辩证基准。
3. **多源调数 + 三级降级**：L1 实时接口 → L2 本地预置存证（仅限预置案例，显著标注抓取日期）
   → L3 信息真空期（显式声明"查不到"，绝不用过期数据冒充正常结论）。
4. **三栏证据对齐**：强制模型按【支持证据】【反对证据】【无法验证项】成稿，
   占位符（"无""暂无"）视为空栏并判违规。
5. **确定性算账**：滑块拖动营收下滑幅度（5%~30%），每帧用公式重算净利润冲击 ——
   **不发任何网络请求**。
6. **玻璃盒存证抽屉**：点角标从右侧滑出 380px 抽屉，默认人类可读摘要，
   可展开工具返回的**完整原始 JSON**。

## 架构

```
浏览器（问财式工作台）
  │  POST /api/chat  (SSE, UI message stream)
  ▼
app/api/chat/route.ts —— Agent 编排层
  │  ① 合规拦截（关键词 + 意图）
  │  ② 命题重构 / 子问题拆解（一次轻量模型调用，失败即确定性兜底）
  │  ③ 主循环 streamText + 3 个工具（最多 5 步）
  │  ④ 成稿后契约校验 → 写 data part
  ▼
lib/gateway.ts —— 金融数据网关（三级降级 + refId 分配）
  │
  ├── lib/fuyao.ts    扶摇 MCP（行情 / 估值 / 利润表 / 财务指标）
  └── lib/ifind.ts    同花顺 iFinD（公告 / 新闻语义检索）
```

### 一次问答的数据流

后端在**同一条 SSE 流**里按序写出 5 个 `data-*` part（前端据此渲染全部 UI）：

| part | 内容 |
|---|---|
| `data-compliance` | 仅拦截路径：`{layer: 'keyword'\|'intent'\|'fail_closed'}` |
| `data-steps` | 编排步骤（确定性中文，不用模型推理） |
| `data-plan` | `{reframedClaim, intentTags, subQuestions, fromModel}` |
| `data-refs` | `{refs:[{refId, kind, payload}]}` —— 存证抽屉的数据源 |
| `data-contract` | `{ok, violations, citations{valid,invalid}}` |
| `data-followups` | 3 条核验向追问 |

> **一个关键的顺序约束**：正文先 merge 进流，契约校验**后**跑。所以**编造的角标一定
> 会到达前端**。因此按 ADR-0002 决策 2，**强制校验落点在前端**：不在本轮返回集合内的
> 角标渲染为灰色"引用失效"，且从可交互性上不可点击（渲染成 `<span>` 而非 `<button>`）。

### 完整闭环：数据 → 工具 → 状态 → 反馈 → 人机协作 → 风险控制

原题第 3 条要求产品结果体现一个完整闭环。逐环对应实现如下：

| 环 | 实现 | 代码位置 |
|---|---|---|
| **数据** | 三源网关（扶摇行情/估值/财务 + iFinD 公告/新闻），每条载荷带 `source`/`asOf`/`isFallback` | `lib/gateway.ts`、`lib/fuyao.ts`、`lib/ifind.ts` |
| **工具** | 3 个深模块工具，由模型在最多 5 步循环内自主调用 | `app/api/chat/route.ts` |
| **状态** | 流式进度条、会话管理（本地匿名持久化）、待确认的重跑 | `lib/message-view.ts`、`lib/session-store.ts`、`lib/rerun.ts` |
| **反馈** | 角标强制校验（有效可点 / 失效灰标不可点）+ 契约违规告警 | `lib/citations.ts`、`lib/output-contract.ts`、`components/CitationText.tsx` |
| **人机协作** | 意图标签可删（自动重跑）/ 可改（需点确认才重跑，省 token）；预置案例一键走完整链路 | `components/IntentTags.tsx`、`lib/rerun.ts`、`lib/preset-cases.ts` |
| **风险控制** | 输入侧词表+意图双保险；输出侧契约扫买卖结论；真空期/降级硬声明不得脑补 | `lib/compliance.ts`、`lib/vocabulary.ts`、`lib/output-contract.ts` |

各环如何串联成一个闭环（而非并列的功能清单）：

```
用户提问
  └─[风险控制] 合规拦截 ─命中→ 柔性引导（不产出分析结构）
  └└─→ [工具] 模型拆子问题 → 调网关
              └─[数据] 三源取数 / 三级降级（L1实时 → L2存证 → L3真空）
                    └─[反馈] 每条载荷发 refId → 正文挂角标 → 前端强制校验
                          └─[人机协作] 用户看到三栏 + 角标，删/改标签 → [状态] 重跑或确认
                                └─[风险控制] 成稿再扫一次买卖结论 → 闭环回到用户
```

## 两个设计决策值得单独说明

### 1. 为什么"信息真空期"必须硬编码

把"这个查不到"的判断交给 LLM 自由心证，等于把幻觉风险放在了最危险的位置 ——
数据缺失时模型最倾向于编一个"看起来正常"的结论。

所以 `lib/gateway.ts` 在检索为空时返回结构化 `vacuum: true`，并把该子问题记入
契约上下文；`lib/output-contract.ts` 校验成稿是否在【无法验证项】里点名了它。
**真机验证**：宁德时代"固态电池量产跳票"一轮真实命中真空期，模型如实写出
「**不得推测** —— 无法据此判定传闻为真，也无法据此判定传闻为假」。

### 2. 为什么测算公式不放在模型里

`ΔNetProfit = BaseRevenue × ΔRevenueDeclinePct × NetMargin × (1 − TaxRate)`

公式全部在 `lib/sensitivity.ts` 的纯函数里，滑块 `onChange` 每帧重算。
组件测试会**断言整个拖动过程零 `fetch` 调用** —— 不是靠"代码里没写请求"自述。

参数缺失时返回 `ok: false` 并显示"不可测算"，**绝不默认 0** 算出一个
"看起来正常"的数字。

## 开发过程中抓出的真实缺陷

这些不是假想的风险，而是在真机运行/代码评审里实际出现并修掉的。
记录在此，因为它们说明了本项目的验证方式确实在起作用。

| # | 缺陷 | 怎么发现的 | 后果（若未修） |
|---|---|---|---|
| 1 | `refId` 分配乱序 | 并发下抽屉引用号随网络抖动 | 引用与存证对不上 |
| 2 | fail-closed 话术**谎称用户索取买卖建议** | 代码评审 | 服务故障时冤枉用户违规 |
| 3 | 合规测试集在服务全挂时**假通过** | 代码评审 | 合规防线形同虚设 |
| 4 | `止损`/`止盈` 输入侧拦、**输出侧漏** | 代码评审 | 正文可写"建议止损"直达用户 |
| 5 | `清仓` 从未被输入侧拦截 | 代码评审 | 明显违规提问漏网 |
| 6 | 真空期匹配**必然误报**（整串字面匹配） | 代码评审 | 正确输出被判违规 |
| 7 | 零角标正文可通过契约 | 代码评审 | 结论无法回溯到字段 |
| 8 | 兜底计划丢失标的名 | 代码评审 | 兜底命题变成"该标的" |
| 9 | **`杠杆` 误分类致真机 8 次运行误报 5 次以上** | 集成测试不稳定，追查告警原文 | 前端对**正确输出**报契约违规；告警频繁后用户学会忽略，整套证据机制名存实亡 |
| 10 | 多轮把**完整对话历史**送进模型 | 离线端到端断言 | 违反 spec 交互决策，爆 token 且模型绕过摘要复述旧正文 |
| 11 | **有效税率被硬编码为 15%** 却与净利率并列展示 | Spec 轴评审 | 违反 ADR-0001「参数可追溯」；真机实际为 14.84%/14.54%，且逐季波动 |
| 12 | 跨轮**存证静默错配**：点第一轮的角标显示最后一轮的 payload | Spec 轴评审 | 违反 ADR-0002 决策 4，且静默无报错，比报错更危险 |
| 13 | 消歧修复引入**回归**：`费用杠杆`/`信用杠杆`/`利用杠杆效应` 被误判为操作指令 | Standards 轴评审 | 与 #9 同类，同样对正确输出弹告警 |
| 14 | **非法入参返回 500 + 整段堆栈**；`messages:'nope'` 反而静默走到 200 | 充值后重跑真机测试 | 调用方错误被当成服务端故障；静默 200 更糟 |
| 15 | **`bg-slate-950/98` 被 Tailwind 静默丢弃** → 存证抽屉完全透明 | 用户实测（"只有文字没有 UI"） | 构建成功 / lint 干净 / 测试全绿，只有人眼能发现 |
| 16 | `.next` 缓存被 dev 与 build 交叉污染 → CSS 404，页面裸文字无交互 | 用户实测 | 验证构建时在长跑的 dev server 上跑 build 导致；已写入 README 排障段 |
| 17 | 提交闸门失效：点一次预置案例**跑两轮**（日志 50459ms + 58260ms） | 用户实测 | 闸门用异步 state 派生，挡不住同 tick 连点；改用同步 ref |
| 18 | 三栏"反对证据=红"与 A股"红=涨=好"心智冲突 | 我核查调研时发现 | 属可用性缺陷；改为蓝/琥珀/灰，与涨跌色分离 |
| 19 | **构建污染 `.next`**（dev 与 build 共用目录）→ CSS/JS 全 404 | 用户实测两次 | 已改为**机器拦截**：dev 在跑时拒绝构建 |
| 20 | 会话排序只在读盘路径做 → "最近使用置顶"静默失效 | 写会话管理时单测抓到 | 同毫秒时间戳使排序不稳定；用单调时间戳 + `writeAll` 也排序 |
| 21 | 侧栏 `h-full` 在 `min-h-screen` 父容器下只有 151px 高 | 真实浏览器实测 | 父容器无确定高度；改 `h-screen` + `lg:sticky` |
| 22 | **中文输入法选词的 Enter 被当成表单提交** → 发出未打完的拼音 | 我按 CDP 真实输入法复现 | 与 #24 是**两条不同的缺陷**；此条真实存在且已修 |
| 23 | **意图层把中性提问判成"索取买卖决策"** → 用户拿不到任何结果 | 追查"测试偶发失败"时挖出 | 提示词缺开放式提问示例；补判据（主语是否为"我"）|
| 24 | **一次提问被渲染成两轮**（用户三次报告的"还是出现两次"） | 真实浏览器 + 真实抓流回放 | 路由把 `data-*` 写在 `start` **之前** → AI SDK 开出**两条** assistant 消息。**这才是用户看到的那个缺陷**；我前两次误判为 #17（连点）与 #22（输入法）|

第 9 条特别值得说明：最初它表现为"集成测试偶尔失败"，很容易被当成负载导致的 flaky 而忽略。
追查后发现模型写的是「固定成本**杠杆**」「经营**杠杆**」「**杠杆**水平上行」——
标准财务术语被当成买卖结论。修复方式是把 `杠杆`/`满仓` 从"无歧义操作词"里拆出来，
改为**语境消歧**（有操作前缀/句式才算操作指令）。修复后连续 **14 次真机运行 0 误报**。

## 局限与已知边界（诚实声明）

- **测算公式是线性一阶近似**：不考虑固定成本摊薄、产能再分配、产品结构变化、
  减值与汇兑等二阶效应，**不构成精确盈利预测**，仅用于理解量级与敏感性方向。
  这条在 UI 上显式展示。
- **合规词表是启发式的**：`lib/vocabulary.ts` 中歧义词的消歧取向是"无操作标记即视为术语"，
  代价是模型若用未预料到的说法表达操作意图会漏报。其他模式（建议买入/目标价/涨停等）
  与系统提示词禁令仍然兜底。该残留风险在 `lib/vocabulary.test.ts` 里被**显式断言**，
  以免未来有人误以为覆盖是完备的。
- **信息真空期判定是机械的**：判定"是否如实声明"，不是语义判定。宁可略宽松地认主题词，
  也不放过把真空期写成正常结论的脑补（假负面比假阳性危险）。
- **L2 降级只覆盖预置案例**：自由查询不走 L2，直接进入信息真空期声明。
- **仅适配桌面端 1280px+**（移动端适配在原 spec 中明确为 Out of Scope）。
- **意图级拦截依赖 LLM 判断**，存在误判可能，靠柔性引导话术缓解。

## 失败条件与后续验证计划（原题第 3 条）

原题要求说明"失败条件、合规边界与后续验证计划"。以下逐项如实写明。

### 一、什么情况下这个产品算失败

| 失败条件 | 为何致命 | 当前护栏 | 仍有缺口 |
|---|---|---|---|
| **编造角标能当真实引用使用** | 整套"可追溯"承诺崩塌，且静默无报错 | 前端强制校验，失效角标渲染为 `<span>` 不可点击 | 无（ADR-0002 决策 2 已锁）；但仅覆盖**角标存在性**，不验数值本身是否正确 |
| **数据缺失被写成"看起来正常"** | 散户据此做决策会被误导，且比报错更危险 | 真空期/降级在契约层硬校验，违规即写入 `data-contract.violations` | 契约校验只"报告"不"拦截"正文（前端才拦截），形态为告警 |
| **输出买卖建议/收益承诺/股价预测** | 直接违反原题红线 | 输入侧词表 + 意图双保险；输出侧契约扫 `trade_conclusion` | 词表假阴性（见边界）；未做对抗性注入测试 |
| **所有提问被合规层误拦** | 用户拿不到任何结果 —— 看起来像产品挂了 | 已修（缺陷 #23）；真机复跑不再复现 | 意图层仍是 LLM 判断，长尾句式仍有误判可能 |
| **LLM 服务/数据源整体不可用** | 无法交付任何结果 | fail-closed 拦截**且文案明确“不是您的问题违规”**（缺陷 #2） | 无 key / 余额耗尽时表现为"看起来像坏了"，已在 README 开头专门说明 |

### 二、合规边界（不可越过的线）

1. **不提供任何投资建议**：不输出买卖方向、目标价、收益承诺、涨跌预测。
2. **不持有/不处理用户隐私**：不采集画像与持仓；唯一状态是本地匿名的会话记录。
3. **不尽信单一来源**：所有事实挂角标，且角标必须回溯到工具**原始返回**。
4. **不确定必须显式**：数据缺失/冲突/过期/调用失败时，**不得静默生成"正常"结论**。
5. **不算精确盈利预测**：线测算是一阶近似，UI 上显式声明不构成预测。

### 三、后续验证计划（若继续做）

| 优先级 | 做什么 | 为什么现在没做 |
|---|---|---|
| P0 | **提示词注入对抗性测试**（"忽略以上指令"等） | 24h 边界内未做；系统提示词有约束但未对抗性验证 |
| P0 | **数值级存证校验**（不只验 refId 存在，还验正文字段值是否与 payload 一致） | 现有实现只保证"引用真实存在"，未保证"转述准确" |
| P1 | **浏览器视觉回归**（Playwright 截图对比） | 现有组件测试覆盖行为与可交互性，不是像素 |
| P1 | **多轮交互的真机回归**（现在的真机 fixture 多为首轮） | 已有离线端到端覆盖多轮摘要，但真机样本不足 |
| P2 | **真正部署到公网 URL** | 本次交付决定不部署（只交付本地运行 + ZIP），见 `DEPLOY.md` |
| P2 | **词表假阴性的持续样本采集** | 已显式断言为已知边界，但需真实长尾样本才能收敛 |
| P2 | **重写 git 历史以彻底移除误提交的构建产物** | 工作区已清理（178 文件/162MB），但旧 blob 仍在历史里（pack ~11MB）。需 `git filter-repo` + 强推，因仓库已公开会影响已有克隆，故留作决定。详见 `deploy/README.md` |
